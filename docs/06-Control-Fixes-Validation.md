## 本轮行为变化

| 条件 | 风扇 PB5（低电平开） | 低温继电器 PB6（低电平开） |
|---|---|---|
| 温度有效且高于阈值+1，CO2正常 | 开 | 关 |
| CO2有效且超过阈值，温度正常 | 开 | 关 |
| 两项都需要通风 | 开 | 按温度条件判断 |
| 两项均正常 | 关 | 温度低于阈值-1时开，否则关 |
| 温度无效，CO2有效且超限 | 开 | 关 |
| 温度与CO2都无效 | 关 | 关 |

保留原有判断边界：等于温度阈值±1时不触发对应请求，等于CO2阈值时不请求。
低温继电器用途沿用原项目，未增加它与通风之间的互锁。

LED 新配置的默认目标统一为200。已有有效EEPROM目标仍优先；旧配置保存500时，
烧录后继续是500属于预期，不能通过只修改LED_Init来覆盖。
正常PID计算使用真实时间间隔，超过5秒则清除旧积分/误差历史并按一个1秒周期恢复。
当前默认Ki/Kd仍为0，尚未证明实际灯带闭环整定完成。

水泵模式值保持0/1/2；App模式1改为“脉冲灌溉”，执行结束后设备自动回到关闭。
`water_vol` 是模型估算的补水量（L），不代表流量计测量值；本轮未校准流量或改变灌溉算法。

## 条件允许时再进行的逐项验证

使用真实配置工程 `E:\fuchuang\code\IOT5-smart2-IOT-final` 的新HEX。

1. 启动：PB5/PB6在GPIO初始化时为高电平关闭；观察是否还有启动误动作。
2. 风扇：保持CO2正常，通过App把温度阈值调到明显低于当前温度（至少低2°C）；
   等待STM32处理并上报后，风扇应持续开启，不应被后执行报警立即关闭。
3. 风扇：把温度阈值恢复到明显高于当前温度，确认CO2也未超限，风扇应关闭。
4. CO2：保持温度正常；只在传感器确实超过可设置阈值时验证CO2通风请求。
   若没有可用真实条件，用主机测试结果作为逻辑证据，不强行制造气体环境。
5. 继电器：低温条件触发后再转为正常/高温，确认PB6明确关闭。
   不连接未知用途的负载来做此测试，可先测控制引脚。
6. 无效数据：拔掉DHT11并等待采集判定失效，温度对应请求撤销；
   CO2若有效且超限，应仍能保持风扇开启。
7. LED：用Keil观察 `led_ctrl.target_lux`，确认来自有效EEPROM或默认200；
   保留目前Ki/Kd=0，先验证调光方向和模式切换，不在本轮重新整定。
8. App：水泵按钮显示“脉冲灌溉”，补水量显示为估算值；
   在已有水路正常的条件下确认脉冲结束后状态最终回到关闭。
