# 2026-11-01 传感器数据模型整理与验证

## 这次改动的目的

现有板子仍然使用 STM32F103C8T6、ESP8266、DHT11、JW01、模拟光照和土壤湿度传感器。
这一轮先完成传感器数据的统一，作为以后更换主控和传感器时能继续使用的软件基础。
配置参数、执行器运行状态的统一留到后续单独实施，本次没有把三件事一起重构。

原来 `main.c` 定义 `temp`、`humi`、`light`、`moist`、`ppm`、`sensor_valid`，显示、报警、
水泵、通风和 OneNET 模块通过各自的 `extern` 声明读取这些变量。采集调用和滤波历史也放在主程序。

现在由采集服务保存一份 `SensorData`。主循环负责在原有时间点调用采集服务，
显示、控制和上报从相同的数据入口读取。这样更换 DHT11 时，主要调整采集服务的驱动适配，
其他模块继续读取已经定义好单位的温湿度字段。

## 数据结构怎么理解

```c
typedef struct
{
    uint8_t temperature_c;
    uint8_t humidity_pct;
    uint16_t light_lux;
    uint16_t soil_moisture_pct;
    uint16_t co2_ppm;
    uint8_t valid_mask;
} SensorData;
```

这里可以按你熟悉的 C 结构体理解：把属于同一份环境读数的成员放在一起。
后缀 `_c`、`_pct`、`_lux`、`_ppm` 分别说明摄氏度、百分比、光照单位和浓度单位。
当前类型沿用原来的整数精度；将来换 SHT30 后若希望保留小数，需要明确调整数据契约、
格式化显示和上报精度，不能只更换驱动后就认为小数会自动保留下来。

`valid_mask` 仍只表示可可靠判断的温度、湿度和 CO2 状态：

| 位 | 值 | 意义 |
|---|---:|---|
| bit0 | 1 | 本次 DHT11 温度读取成功 |
| bit1 | 2 | 本次 DHT11 湿度读取成功 |
| bit3 | 8 | 本次取得 CO2 驱动提供的新数据 |

全部成功通常为 `1 + 2 + 8 = 11`。DHT11 两项一起失效、CO2 正常时通常为 8；
CO2 没有新数据、DHT11 正常时通常为 3。读取失败仍保留最近一次数值，
消费者通过有效位判断温度和 CO2 是否可参与相应控制。光照、土壤仍不做拔插有效性判断。
CO2 有效性的具体帧校验仍由现有 USART3 驱动负责，本轮没有修改帧解析或超时规则。

`water_vol` 是灌溉算法估算的补水量，属于业务计算结果，所以暂未合并进传感器结构体。

## 四个接口怎么使用

```c
SensorService_Init();
SensorService_Poll();
SensorService_ReadLight();
const SensorData *sensors = SensorService_GetData();
```

- `Init`：在启动时设置原来的初值，并清空滤波历史。有效位初始为 0，初值不代表真实有效测量。
- `Poll`：依次读取土壤、CO2、DHT11、光照。调用顺序沿用原来的主循环。
- `ReadLight`：自动 LED 控制周期内额外采集光照；返回值继续决定本次是否执行 PID。
- `GetData`：得到当前数据的只读视图。例如 `sensors->temperature_c` 表示通过指针读取温度成员。

`const SensorData *` 使消费者不能通过这个指针直接赋值修改读数。
实际存储在服务内部定义为 `static`，其他源文件也无法直接通过 `extern` 引用它。
目前只有主循环调用采集服务；中断继续更新驱动接收缓冲，没有在中断中直接采集或更新本结构体。

返回指针指向的是当前数据，不是历史副本。下一次采集会更新相同存储。
如果以后引入多个任务，或者需要保存某一时刻的记录，需要再增加数据复制和同步机制。

## 对现有行为的影响

主要目标是整理结构，采集与业务行为保持原样：

- 约每 5 秒采集并上报一次；自动 LED 的额外光照采集仍约每 1 秒一次。
- DHT11/CO2 沿用现有三点滤波，包括失败后保留滤波历史的行为。
- 仍使用旧版 OneNET，JSON 属性名、格式、顺序和有效位不变，无需修改云端物模型。
- EEPROM 仍为原来的 v2 布局，有效已保存参数继续优先。
- 没有修改传感器驱动算法、网络重连调度、PID 算法或灌溉状态机。

同时修正了按键下边界：在本机温度阈值设置中，原代码阈值为 0 时继续按减号会写 `temp = 0`，
误修改实测温度；阈值为 1 时减 2 还会发生无符号下溢。现在仅修改阈值，并在下边界限制为 0。
其余按键参数的边界和选择行为没有在本轮扩展调整。
