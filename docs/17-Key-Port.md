## 1. 本轮要解决的依赖

原Key_Scan同时读取具体GPIO并执行按键状态机。此次把四个引脚的读取及低电平有效转换集中到app_key_port.c，Key_Scan通过标准C接口获取逻辑按下状态。

```text
PA4 / PA5 / PB7 / PA6
        ↓ 当前F103适配：app_key_port.c
KeyPort_ReadPressedMask：bit0..3，1按下/0松开
        ↓
Key_Scan：原计数消抖与短按/长按标记
        ↓
Key_Func：原翻页、选项、参数与模式操作
```

上层状态机继续按逻辑键号处理，未来更换引脚、端口或有效电平时优先修改适配文件。初始化与扫描调度仍由当前工程负责。

## 3. 四个键与掩码

```c
#define KEY_PORT_KEY1_MASK (1U << 0)
#define KEY_PORT_KEY2_MASK (1U << 1)
#define KEY_PORT_KEY3_MASK (1U << 2)
#define KEY_PORT_KEY4_MASK (1U << 3)
#define KEY_PORT_ALL_MASK 0x0FU
uint8_t KeyPort_ReadPressedMask(void);
```

| 逻辑按键 | 当前引脚 | 按下电平 | 原用途 |
|---|---|---|---|
| 1/bit0 | PA4 | 低 | 翻页 |
| 2/bit1 | PA5 | 低 | 参数选项、LED手动亮度 |
| 3/bit2 | PB7 | 低 | LED模式、参数增加 |
| 4/bit3 | PA6 | 低 | 水泵模式、参数减少 |

例如0x01为键1按下，0x04为键3按下，0x05为两者都按下；0为全部松开，0x0F为全部按下。高四位固定为0。

一次调用依次读取PA4、PA5、PB7、PA6，各一次，保持原顺序。四次GPIO读取是顺序执行的，不是物理上的同时采样；返回值也不是经过消抖的按键事件。当前接口不提供硬件故障或按键接线检测。

接口不等待、不分配内存、不配置引脚、不读写按键状态机或执行器。Key_Scan把对应位转换为各Keys[i].Pin_state的0/1，四项赋值完成后进入原状态机。

## 4. 原按键状态机怎样工作

当前由TIM1回调调用Key_Scan，原定时器预分频/周期保持不变。消抖与长按依据扫描计数，不引入新的毫秒时基。

- State=0：按下期间累计Presstime；松开时若Presstime大于3才转入State=1，否则清除该计数。
- State=1：松开期间累计Releasetime，大于3后进入State=2。
- State=2：设置ClickFlag；Presstime大于150时同时设置LongClickFlag，再清除按下/释放计数。
- 主循环Key_Func按原顺序处理事件并清理对应标记和状态。长按仍在松开后走原事件流程，没有改为按住即触发或持续连发。

本轮保留这些既有规则，包括扫描与主循环之间的事件消费方式。没有重写消抖算法，也没有宣称附加函数调用后的CPU指令时序逐周期完全相同。
