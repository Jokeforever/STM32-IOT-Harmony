# 本地优先启动与 MQTT 重连

2026-11-17 用户确认修正版实板可用。该阶段让 STM32 在等热点或云端应答期间继续提供串口屏操作、传感器采样、自动控制和 OLED 显示。沿用设备诊断版串口屏工程。

## 启动顺序

主控完成硬件初始化、恢复 24C02 配置并初始化输出后，启动串口触摸接收，看门狗和周期采集由主循环执行。`AppNetworkStartup_Poll()` 按阶段推进：

1. 检查 ESP8266 的 AT 应答，设置工作模式和 DHCP，加入热点。
2. 清理旧 TCP 连接，重新建立到 OneNET 的 TCP 链路。
3. 发送 MQTT 登录包，收到有效 CONNACK 后发送属性设置订阅。
4. 完成后开放普通属性上报和云端命令处理。达到阶段重试上限时先进入离线等待，约 10 秒后再从 AT 开始。

联网和重连共享同一套状态推进逻辑。握手期间由启动模块处理 USART2 应答，普通上报和命令收包在握手结束后开启。UART 解析使用有界接收缓冲，允许登录确认分段到达。

## 设置应答与上报

实测初版曾出现从 App 设置照明、水泵或阈值后收到应答，但上报缺失并出现离线。代码检查发现，两次发送在 ESP8266 上可能重叠。修订版按同一串口发送流程执行设置应答和属性上报，每帧等到 `SEND OK` 再返回，随后才允许下一次 `CIPSEND`。`SEND OK` 是 ESP8266 的发送完成回报。遇到传输失败，待上报标志保留，主控关闭旧 TCP 后重连并补报。设备诊断页区分 OneNET 当前状态与各阶段最近一次结果。 [Espressif ESP8266 TCP/IP AT 示例](https://docs.espressif.com/projects/esp-at/en/release-v2.2.0.0_esp8266/AT_Command_Examples/TCP-IP_AT_Examples.html)

## 目标板与复验

- OLED 16×16 汉字按上下各 16 字节绘制，字库每半字由原先的 32 字节改为 16 字节，去掉 1,376 字节未使用的补零。原字形数据保留。最终 Keil 链接区占 64,752 字节，64 KB 配置下余 784 字节。
- Keil 完整重编译为 0 错误、5 条既有 cJSON 警告。13 套既有主机回归及冷启动、命令回传专项通过。专项模拟热点等待与恢复、分段 MQTT 确认、设置回复之后的上报，以及发送失败后重连补报。
- 用户确认修正版实板可用。复验时只更新 STM32 固件。关热点冷启动，检查本地触摸和采样。恢复热点后，分别通过 App 设置照明、水泵和阈值，核对 OneNET 生效值及在线状态，再确认运行中断网后能恢复。
