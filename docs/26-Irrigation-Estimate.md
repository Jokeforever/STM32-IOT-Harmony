# 灌溉补水量和时长估算

真实 STM32 工程中的灌溉估算重构已通过用户实物复验。

## 代码怎么走

`bump.c` 在需要启动灌溉时，读取当前土壤湿度和已校验的干旱阈值 BL、湿润阈值 BH。两个灌溉模式都调用 `Irrigation_Estimate()`，取出补水量估算值和毫秒计时目标。估算为零时，水泵控制模块将 PB1 拉低。

`mw_irrigation.c` 只处理计算。湿度低于 BL 时，以 BL 为计算起点。湿度在 BL 和 BH 之间时，按当前湿度到 BH 的差值计算。达到 BH 时返回零。计算结果大于零且不足 0.10 L 时，按 0.10 L 计。

| 当前土壤湿度（BL=25%、BH=80%） | 估算补水量 | 计时目标（约） |
|---|---:|---:|
| 0% 或 25% | 0.44 L | 22 秒 |
| 50% | 0.24 L | 12 秒 |
| 79% | 0.10 L | 5 秒 |
| 80% 及以上 | 0 L | 0 秒 |

计时目标沿用 1.2 L/min 的配置流量和原来的浮点换算、毫秒截断。自动模式连续开泵，脉冲模式的总计时包含停泵时间。界面和 OneNET 上的水量字段表示估算量，脉冲模式的实际出水量需要另行测量。

估算函数仅依赖标准整数类型。换板时可直接复用，板级代码负责提供传感器读数、毫秒时钟和水泵输出。

## 自动检查

13 套固件主机回归通过。控制集成共 384 项断言。Keil 完整重编译为 0 错误、5 条警告。

逐一比对了湿度 0～100%、阈值 0～100% 且 BL ≤ BH 的 520,251 种组合，估算水量和两条旧路径的毫秒结果逐项相同。新旧代码也均通过 PB1 开关判据、10 ms 停泵边界、脉冲相位、自动检查间隔、计数回绕和湿润阈值的主机回归。

## 烧录后的实物复验

烧录真实工程生成的 `MDK-ARM/IOT/IOT.hex`，逻辑分析仪 D7 接 PB1 并共地。先用土壤湿度 0%、BL=25%、BH=80% 的条件复测。

1. **脉冲灌溉**。观察约 0.5 秒高、1.5 秒低，约 22 秒总计时内有 11 个完整的开泵脉冲，结束后保持低电平。
2. **自动灌溉**。等待一次自动检查，单次高电平约 22 秒，到时拉低。
3. **达到湿润阈值**。水泵停下后，让 BH 等于当前湿度。湿度保持 0% 时，先把 BL 调为 0%，再把 BH 调为 0%。等待下一次自动检查（超过 30 秒），D7 应保持低电平，估算补水量应回到 0。
4. **估算值**。恢复 BL=25%、BH=80%，在湿度为 0% 时再触发一次灌溉。内部估算约为 0.44 L，OLED 和 OneNET 按一位小数显示和上报。OLED 应显示 `0.4`，App 收到新上报后应显示 `0.40 L`。

## 本轮验收结果

用户确认四项实物复验均通过，覆盖脉冲灌溉、自动灌溉、估算补水量显示以及达到湿润阈值时保持关泵。

在土壤湿度 0%、BL=25%、BH=80% 时，脉冲波形为约 0.5 秒开泵、1.5 秒停泵，自动模式单次高电平约 22 秒。估算值在 OLED 上显示 0.4，App 显示 0.40 L。
