## 1. 本轮目标

PID算法此前已独立，本轮把LED运行逻辑中的毫秒时基、PWM比较值、启动/停止和关灯引脚动作迁到一个端口实现中，让业务表达“输出多少占空比”，不直接指定TIM3和PA7。

```text
RuntimeConfig → LED模式/手动/PID适配 → LedPort_*接口
                                  → 当前F103实现 → TIM3_CH2、PA7、HAL时基
```

这一步隔离运行期输出与时基。LED_Display仍使用原OLED实现，Core/Src/LED.c通过oled.h仍可能间接包含HAL声明；整个LED源文件尚不是完全独立于平台的纯C模块。LED.h公共头文件已不依赖HAL、按键或OLED。

## 3. 四个接口

```c
uint32_t LedPort_NowMs(void);
void LedPort_Enable(void);
void LedPort_Disable(void);
LedPortResult LedPort_SetDuty(uint16_t duty_permille);
```

NowMs透传当前HAL毫秒时基，PID继续使用uint32无符号差值处理回绕。Enable仍调用原PWM启动动作；Disable严格维持先HAL_TIM_PWM_Stop、再PA7拉低的顺序。启动/停止函数继续沿用原来的HAL错误处理方式，本轮没有新增硬件故障反馈。

SetDuty返回值明确为：LED_PORT_OK=0，表示当前周期可支持且CCR已写入；LED_PORT_INVALID_PERIOD=1，表示周期不受支持且不写寄存器。它不是对LED实体亮度的测量结果。LED_SetPWM仍保留原void API，只在合法写入后更新逻辑pwm_value。

## 4. 从计数值变为统一逻辑量

接口输入是0～1000千分比，1000表示请求100%，300表示请求30%。LED业务层的PWM_MAX仍为1000，手动百分比乘10、PID限幅和参数均保持原规则。

```text
period = ARR + 1
CCR = floor(period × duty_permille / 1000)
```

| 周期 | 逻辑输入 | CCR |
|---|---:|---:|
| 当前ARR=999，1000个计数 | 300 | 300 |
| 测试ARR=9999，10000个计数 | 300 | 3000 |
| 当前ARR=999 | 1000 | 1000 |

因此当前有效配置下，旧比较值与新输出逐项一致。将来换为不同周期，PID和手动亮度仍使用相同逻辑量。整数换算向下取整，量化误差小于一个计数；低分辨率周期不能凭接口创造更高分辨率。

led_ctrl.pwm_value保存的是0～1000逻辑占空比，未来周期变化后它与实际CCR可以不同。旧全局变量ccr仍为兼容保留，在手动路径里同样表达该逻辑量。

## 5. 量程与当前适配边界

LED_SetPWM先把有符号输入钳制到0～1000，再转uint16传给端口。端口自身也将大于1000的输入钳制为1000。PWM_MAX显式保持有符号比较，避免有符号PWM与无符号常量混用。

当前实现专用于F103的16位TIM3、非反相PWM1，支持ARR=0～65534。ARR=65535时，要实现精确100%需要超出16位的ARR+1比较值，故本轮明确返回错误；更大或无效的ARR同样拒绝。当前板子的ARR=999处于支持范围。

拒绝时不会写CCR，LED_SetPWM也不把新请求写进pwm_value；初始化仍保留原默认300。此保护不会自动停PWM，也未新增App告警。以后换其他定时器、极性或32位周期，需提供并验证相应适配，不能直接假定此F103实现适用。
