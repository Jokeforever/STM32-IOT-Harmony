# PID算法与LED驱动分离：学习说明和本轮验收

日期：2026-11-07。阶段：本轮五项用户实测全部通过，已同步仓库脱敏副本。

## 这一步带来什么

此前LED_Update同时读取配置、读取HAL时间、计算PID并写定时器寄存器。
现在把PID计算移到独立模块：算法接收参数、测量值和时间戳，返回本次是否产生新输出。
LED适配层负责从当前工程取得这些输入，并把结果送给PWM驱动。

这使算法能够单独运行测试，也方便以后更换主控时复用。当前硬件仍是F103与ESP8266，
本轮没有更换硬件或引入RTOS。实际灯带与光敏传感器的光学耦合问题、PID整定需求继续保留。

```text

  → LED_Update
```

mw_pid.c不读取HAL、GPIO、定时器、传感器或AppConfig，也没有全局控制器实例。
每个使用者分别提供PID_State，所以将来可以创建多个互不影响的控制器。

## 参数和状态为什么分开

PID_Config描述这次计算的规则：目标值、死区、Kp/Ki/Kd乘1000的整数、输出上限、名义周期、长间隔阈值。
PID_State描述历史：积分、上次误差、上次时间、是否已经建立历史。

当前LED的参数仍来自上一轮RuntimeConfig。默认目标200 lux、死区20 lux、Kp=1.5、Ki=0、Kd=0，
但已有有效EEPROM参数继续优先。例如原来保存目标500，烧录后仍按500运行。

```c
PID_Config config;
PID_State state;
uint16_t output;

/* 先由调用方填写config：目标、死区、系数、输出和时间规则。 */
PID_Reset(&state, now_ms);
PID_Result result = PID_Update(&state, &config, measured, now_ms, &output);
if (result == PID_OUTPUT_READY) {
    /* 由调用方把output送给自己的执行器驱动。 */
}
```

在实际LED代码里，状态保存为led_ctrl.pid。
若使用Keil观察，原来的led_ctrl.integral、last_error、last_tick、pid_initialized分别对应：

- led_ctrl.pid.integral
- led_ctrl.pid.last_error
- led_ctrl.pid.last_tick
- led_ctrl.pid.initialized

enabled、current_lux和pwm_value仍属于LED运行状态。

## 计算公式沿用原逻辑

误差为目标减测量值。每次正常计算：

```text
error = target - measured
dt = elapsed_ms / 1000
integral += error * dt
P = Kp * error
I = Ki * integral
D = Kd * (error - last_error) / dt
output = P + I + D
```

Ki>0时，积分限制在正负output_max/Ki之间；Ki=0时积分清零。
最后把输出限制到0～output_max，再向零取整，当前LED输出范围仍为0～1000。
本轮没有改成增量式PID，没有新增微分滤波、双向输出或新的抗饱和策略。

算法测量值和目标使用int16_t，系数采用0～10000的整数表示实际0～10。
当前光照驱动最大999 lux，符合这个接口。将来传感器量程/精度改变时，需要检查入参刻度和范围，
不能直接把超范围光照强转为int16_t。更换PWM分辨率时也需检查LED适配层当前int16_t输出接口。

## 必须理解的三个返回值

| 返回值 | 含义 | 驱动应该做什么 |
|---|---|---|
| PID_OUTPUT_READY | 本次完成了计算 | 写入新输出 |
| PID_HOLD | 首个样本、死区或时间未推进 | 保留当前输出，不写未初始化的output变量 |
| PID_INVALID | 空指针或不合法的算法参数 | 保持原状态和输出，检查调用方配置 |

调用方必须检查返回值。HOLD和INVALID都不写output，不能忽略返回值直接使用output。
LED_Update已经按这个规则处理；算法参数由现有经过范围检查的RuntimeConfig构造。

## 保留的时间与死区行为

| 条件 | 行为 |
|---|---|
| Reset后的首个死区外样本 | 建立误差/时间历史，保持当前PWM |
| 误差绝对值≤死区 | 清积分、更新误差和时间，保持当前PWM；保留原初始化状态 |
| 同一毫秒再次计算且在死区外 | 不积分、不微分、不更新输出 |
| 正常间隔≤5000ms | 使用实际dt，包括恰好5000ms |
| 间隔>5000ms | 清旧积分，把上次误差重建为当前误差，再按名义1000ms恢复计算 |
| uint32时间计数回绕 | 用无符号减法计算间隔，沿用原有处理 |

首次建历史会让切入自动后存在一个采样周期的等待，属于保留行为。
死区内保持当前PWM，也不会自动把PWM降到0。
时间戳由调用方提供；算法无法识别跨越完整2^32毫秒的停顿，仍需遵守原有32位时基使用范围。

## PWM适配的一处诊断修正

自动和手动PWM现在都通过LED_SetPWM写入，输出在同一入口限幅并同步pwm_value。
此前手动分支直接写寄存器，pwm_value可能停留在旧自动值；现在它记录实际设置的手动PWM。
手动占空比仍是原来的10×百分比，灯的设定值没有改变。
关闭/常亮/自动的启停逻辑保留，未改变OneNET属性、采样周期或EEPROM格式。
