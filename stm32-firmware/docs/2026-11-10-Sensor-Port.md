## 3. 接口与单位

```c
typedef enum {
    SENSOR_PORT_ERROR = 0,
    SENSOR_PORT_OK = 1
} SensorPortResult;

SensorPortResult SensorPort_ReadTempHumi(uint8_t *temperature_c, uint8_t *humidity_pct);
SensorPortResult SensorPort_ReadCO2(uint16_t *co2_ppm);
SensorPortResult SensorPort_ReadLight(uint16_t *light_lux);
SensorPortResult SensorPort_ReadSoil(uint16_t *soil_moisture_pct);
```

温度为整数摄氏度、空气湿度为整数百分比，CO2为ppm、光照为lux、土壤湿度为整数百分比。沿用原uint8/uint16宽度，没有增加小数、负温度表示或范围钳制。

所有端口统一使用SENSOR_PORT_OK=1和SENSOR_PORT_ERROR=0，调用者显式比较命名常量。成功才更新输出，失败保留调用者原值；空指针直接失败，不进入驱动。温湿度作为一组读取，任一输出指针为空均不采集。

适配层先用局部变量接收驱动输出，确认成功后复制给调用者，避免失败时意外写出的中间数据污染最近读数。没有新增动态分配、等待、重试、滤波或采样。

## 4. 为什么需要显式转换返回值

| 当前驱动 | 原成功判断 | 端口判断 |
|---|---|---|
| DHT11_Read_Data | 等于DHT11_OK，即0 | 成功映射1，其他值映射0 |
| CO2GetData | 非0 | 成功映射1，0映射0 |
| LDR_LuxData | 非0 | 成功映射1，0映射0 |
| TS_GetData | 非0 | 成功映射1，0映射0 |

DHT11的1无响应和2校验错误均失败，不能直接把其原返回值作为端口结果。另三项保留原非0成功规则，不能擅自缩为只有1才成功。

CO2端口仍只调用一次CO2GetData，是否有新帧及消费接收标志仍由原驱动负责。模拟量端口返回成功只说明驱动本次读取成功，不证明探头已连接或校准准确。

## 5. 服务行为保持情况

完整Poll顺序依然是：土壤→CO2→温湿度→光照。主循环约5秒采集上报、LED原1秒周期额外读取光照的调度保持原样。本轮接口仍是同步调用，不承诺非阻塞或固定执行时间。

温湿度及CO2成功后更新原三点中值滤波，置对应有效位；失败保留最近数值和滤波历史，并清除对应有效位。恢复时仍按已有历史运行，并未另加失败清空历史的规则。

光照和土壤沿用原读取/换算及失败保留值，继续不纳入拔插有效性判断。SensorService_ReadLight公开返回值仍为1成功、0失败，单独读光照不改其他读数或有效位。

SensorData和sensor_status位定义保持：温度bit0、湿度bit1、CO2 bit3。三项有效时为11，其他位不使用；仅DHT11失效且CO2仍有效时为8。云端属性、App显示规则和EEPROM格式均保持原样。
